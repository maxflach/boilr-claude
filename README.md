# boilr-claude

Full-stack project scaffolding and Claude Code agent setup. Four skills:

- **`/initproject`** — scaffold a new full-stack project from scratch with agents, skills, and CI/CD
- **`/setup-claude`** — add Claude Code agents and skills to an existing project
- **`/boilr-version`** — check installed versions and available updates
- **`/boilr-update`** — update all skills to the latest version from GitHub

---

## Install

One command — no clone needed:

```bash
curl -s --create-dirs -o ~/.claude/skills/boilr-update/SKILL.md https://raw.githubusercontent.com/maxflach/boilr-claude/main/skills/boilr-update/SKILL.md && claude "/boilr-update"
```

This bootstraps the updater, which fetches and installs all skills from GitHub.

### Alternative: clone and install

```bash
git clone https://github.com/maxflach/boilr-claude.git
cd boilr-claude
claude "read SETUP.md"
```

## Start a new project

```bash
mkdir ~/code/my-app && cd ~/code/my-app
claude
/initproject
```

Claude walks you through the setup, scaffolds the project, creates the GitHub repo, and sets up the agent team.

## Set up Claude in an existing project

```bash
cd ~/code/existing-project
claude
/setup-claude
```

Claude analyzes the codebase, detects the stack, and creates:

- `CLAUDE.md` — project conventions and rules
- `.claude/agents/` — specialized agent team tailored to the project
- `.claude/skills/newfeature/` — feature development workflow

Works with any stack — React, Next.js, Vue, Svelte, Express, Django, FastAPI, Firebase, and more.

---

## Requirements

- [Claude Code](https://claude.ai/claude-code) — installed and authenticated (`claude` in terminal)
- **Node.js** v20+ and **pnpm** (`corepack enable` or `brew install pnpm`)
- **git**
- **GitHub CLI** — `brew install gh` then `gh auth login`
- **Firebase CLI** — `pnpm add -g firebase-tools` then `firebase login` (only for Firebase projects)
- **JDK 21+** — only for the Firebase stack's Firestore rules tests; the emulator rejects older
- **Docker** — only for the two pgvector stacks (local Postgres + pgvector)
- **Go** 1.23+ and **golang-migrate** (`brew install golang-migrate`) — only for the Go + pgvector stack

## What `/initproject` does

You'll be asked:
1. **Stack** — Firebase (Firestore + Functions), Node.js + React (PostgreSQL + Prisma + Express),
   Node + pgvector + MCP, or Go + pgvector + MCP
2. **What are we building?** — paste a Linear ticket (auto-fetched via the Linear MCP) or describe the app's functionality in your own words. This rich description is threaded into `CLAUDE.md` and every agent's context.
3. **Category & purpose** — SaaS / Internal tool / Consumer app, and why you're building it
4. **App name**
5. **Multi-tenant?**
6. **Auth provider** — Firebase Auth, JWT, or None
7. **GitHub visibility** — private or public

Each major phase pauses for your approval. At the end you'll have:

- Full project scaffold with deps installed
- Git repo on a `develop` branch, pushed to GitHub
- Team of specialist AI agents in `.claude/agents/`
- The `/newfeature` skill ready to use

---

## What `/setup-claude` does

You'll see:
1. **Project analysis** — Claude scans the codebase and shows what it detected (stack, framework, database, etc.)
2. **Coding rules** — you specify any rules to enforce (e.g., "no useEffect for data fetching")
3. **Team selection** — pick which agent roles to create (full team, frontend-only, backend-only, or custom)
4. **CLAUDE.md** — project conventions generated from the codebase analysis
5. **Agent team** — specialized agents with rules tailored to the detected stack
6. **Newfeature skill** — development workflow using the created agents

Each phase pauses for review. Everything is tailored to the actual project — no generic boilerplate.

## Stack Options (initproject)

### Firebase Stack
Firestore + Firebase Functions + Firebase Auth + Firebase Hosting

Best for: real-time apps, rapid prototyping, serverless. No BoilrAPI involved.

### Node.js + React Stack
PostgreSQL + Prisma + Express (BoilrAPI) + React

- Frontend → Firebase Hosting
- API → Firebase App Hosting (managed Node.js)
- OpenAPI docs auto-generated at `/api/doc`
- Frontend client auto-generated by hey-api (no raw fetch calls)

Best for: relational data, complex queries, REST APIs.

### Node + pgvector + MCP Stack
Postgres + pgvector + Drizzle + Express (BoilrAPI) + ingest worker + MCP server + React

- Local dev DB → Docker `pgvector/pgvector` via `docker-compose`
- Frontend → Firebase Hosting, API → Firebase App Hosting
- Ingest/embedding work runs in a separate worker process, never in an HTTP handler
- Embeddings go through a pluggable `Embedder` interface — managed API now, self-hosted later,
  no call sites change
- MCP server exposes the app's tools to Claude, reusing the API's service layer

Best for: semantic search, embeddings, recommenders — while staying in the Node ecosystem.

### Go + pgvector + MCP Stack
Postgres + pgvector + Go API (pgx, chi) + ingest worker + MCP server + React

- Same capabilities and same React frontend as the Node variant; the backend is Go
- Migrations are hand-written `.up.sql`/`.down.sql` for golang-migrate
- Frontend → Firebase Hosting, API → Cloud Run

Best for: the same vector/MCP workloads, for teams that prefer Go.

> Both pgvector stacks start on a local Docker Postgres. Moving to a hosted database later
> (e.g. Neon) is a one-line `DATABASE_URL` swap — Neon is plain Postgres over the wire, so no
> code or schema changes.

## Using `/newfeature`

```bash
cd ~/code/my-app
claude
/newfeature
```

1. Describe the feature, set priority, flag DB changes
2. **Project Manager** (Claude Opus) writes a detailed plan
3. You review and approve
4. A `feature/<slug>` branch is created from `develop`
5. Specialist agents build it — DB → Backend → Frontend → DevOps
6. Each phase pauses for your review
7. **Code Reviewer** checks everything at the end

---

## The Agent Team

| Agent | Model | Role |
|---|---|---|
| Project Manager | Opus | Plans features, orchestrates agents, never writes code |
| Frontend Engineer | Sonnet | React components, hooks, pages |
| Backend Engineer | Sonnet | API routes, business logic |
| Database Engineer | Opus | Schema changes, migrations, queries |
| DevOps | Sonnet | Config, deployment, CI/CD |
| Code Reviewer | Opus | Reviews all changes, enforces hard-block rules |

When using `/setup-claude`, the team is adapted to the project — a frontend-only project gets Frontend + PM + Reviewer, a backend-only project gets Backend + DB + PM + Reviewer, etc.

## The Rules (baked into every project)

### No `useEffect` for data fetching — ever

```tsx
// Never — causes race conditions and memory leaks
useEffect(() => { fetchUser(id).then(setUser); }, [id]);

// Always — use React Query
const { data: user } = useQuery({ queryKey: ['user', id], queryFn: () => getUser(id) });
```

### Pass IDs as props, not full objects

```tsx
// No
<OrderRow order={order} />

// Yes — React Query deduplicates, so this is free
<OrderRow orderId={order.id} />
```

### No prop drilling beyond 1 level

Use a React Query hook (server data) or Jotai atom (UI state) instead.

### Small components — one responsibility, ~150 lines max
